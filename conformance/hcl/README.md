# The HCL contract

`conformance/hcl/` freezes how a FlowDoc is written as a `flowascode_contact_flow`
or `flowascode_contact_flow_module` resource and read back. Two implementations
must agree on every byte of it: `@flow-as-code/hcl` (TypeScript, in this
repository, the studio's third view) and the Terraform provider
`flow-as-code/flowascode` (Go, in its own repository, which vendors this
directory). The provider does not parse `.tf` files: Terraform hands it the
evaluated configuration, and its plan-time `flowdoc` attribute is the parity
oracle, so for every case here the provider plans the golden and must produce
the case's FlowDoc byte for byte. The rules are stated once, here; the two
implementations cite this file rather than each other. ADR-0007 records why
HCL is a view over FlowDoc and not a second format.

## Families

```
hcl/README.md                          this contract
hcl/address-sugar.json                 addresses the TypeScript parser rewrites to a reference key (TypeScript only)
hcl/roundtrip/<case>/case.json         description, the document (a path relative to the case), options, validate expectation
hcl/roundtrip/<case>/bindings.json     reference key -> terraform address expression; a key absent here is unbound
hcl/roundtrip/<case>/expected.flow.tf  the resource, byte-exact, a `terraform fmt` fixed point
hcl/roundtrip/<case>/*.flowdoc.json    optional; a document the case does not borrow from elsewhere in conformance/
hcl/regenerate/<case>/case.json        what the case shows (TypeScript only)
hcl/regenerate/<case>/doc.flowdoc.json the document being written
hcl/regenerate/<case>/previous.flow.tf the companion on disk before regeneration
hcl/regenerate/<case>/expected.flow.tf the companion after: carried values, kept comments, normalized sugar
hcl/parse/<case>/input.flow.tf         a hand-written resource, fmt or not
hcl/parse/<case>/expected.flowdoc.json the document it reads to
hcl/parse/<case>/expected.sidecar.json {refs, lint, tags, instanceId, normalized, keep?}: what the file carried beside the document
hcl/refuse/<case>/input.flow.tf        a resource both implementations refuse
hcl/refuse/<case>/expected-error.json  {code, path?, messageIncludes?}; the code is the cross-language field
```

Both implementations pass `roundtrip`, `parse` and `refuse`. `regenerate` and
`address-sugar.json` describe what the TypeScript side does to a file it is
rewriting, which the provider never does. `options` in a `case.json` may carry
`instanceId` (the expression written for `instance_id`), `tags` and
`lintDisable`: the values a companion carries that the document does not. A
case marked `validate: "skip"` has no provider to resolve yet; the mark flips
to `pass` or `fail` once the provider is on both registries (task B03e).

## The resource

```hcl
# Generated by @flow-as-code/hcl from appointment-line.flowdoc.json.
# Edits to structure regenerate; comments marked @keep survive.

resource "flowascode_contact_flow" "appointment_line" {
  instance_id = var.connect_instance_id
  name        = "appointment-line"
  type        = "CONTACT_FLOW"
  description = "Main appointment line"

  refs = {
    "hours:main-line" = aws_connect_hours_of_operation.main_line.arn
    # TODO: no terraform address for ${cdref:lambda:appointment-lookup}.
    "lambda:appointment-lookup" = null
    "queue:appointments"        = aws_connect_queue.appointments.arn
  }

  tags = {
    team = "cx"
  }

  lint {
    disable = ["prompt-length-3000"]
  }

  action {
    id   = "welcome"
    next = "check-hours"
    message_participant {
      text = "Thanks for calling. Let's get you to the right place."
    }
    error {
      type = "NoMatchingError"
      next = "apologize"
    }
  }

  action {
    id   = "check-hours"
    next = "announce-closed"
    check_hours_of_operation {
      hours_of_operation_id = "hours:main-line"
    }
    condition {
      operator = "Equals"
      operands = ["True"]
      next     = "set-working-queue"
    }
    condition {
      operator = "Equals"
      operands = ["False"]
      next     = "announce-closed"
    }
    error {
      type = "NoMatchingError"
      next = "apologize"
    }
    position {
      x = 540
      y = 120
    }
  }

  action {
    id   = "create-task"
    next = "hang-up"
    generic {
      type = "CreateTask"
      parameters = jsonencode({
        ContactFlowId = "$${cdref:flow:task-flow}"
        Name          = "Follow up"
      })
    }
    error {
      type = "NoMatchingError"
      next = "hang-up"
    }
  }

  action {
    id = "hang-up"
    disconnect_participant {}
  }
}
```

### The file

1. The file is `<name>.flow.tf`, one resource per file, paired with
   `<name>.flowdoc.json` by suffix. Other `*.tf` files in the directory are
   the user's and are never read or written by the pairing.
2. The banner is the two comment lines above, the first naming the document
   file the resource was written from, then a blank line. A regenerated file
   keeps the banner.
3. The resource type is `flowascode_contact_flow` for a document of kind
   `flow` and `flowascode_contact_flow_module` for kind `module`. The label is
   `slugIdentifier(name)` from `@flow-as-code/core`: hyphens become
   underscores, and an underscore is prefixed when the slug starts with a
   digit.
4. Attributes come before blocks. Their order is `provider` (only when the
   user wrote one), `instance_id`, `name`, `type` (flows only: the document's
   `connectType`), `description` (only when the document has one), `state`
   (only when the user wrote one), `external_invocation_enabled` (modules,
   only when the user wrote one), `start` (only when the document's
   `StartAction` is not its first action); then, each after one blank line and
   only when non-empty, `refs`, `settings` (modules), `tags` and the `lint`
   block; then one `action` block per action in document order, each after a
   blank line; then, only when the user wrote them, `lifecycle` and
   `depends_on`, each after a blank line.
5. `instance_id` is written as `var.connect_instance_id` on first generation
   (or the case's `options.instanceId`) and carried verbatim afterwards.
6. `refs` is an object with one entry per entry of the document's `refs`,
   keyed by the reference key (`queue:front-desk`, `module:survey@prod`,
   `view:form@1`: the token without its `${cdref:` wrapper), keys in byte
   order and always quoted. The value is the terraform address bound to the
   key, or `null` for an unbound key, with the comment
   `# TODO: no terraform address for ${cdref:<key>}.` on the line above it.
   The map is omitted when the document has no references.
7. `settings` is `jsonencode({ ... })` of a module's `content.Settings`,
   omitted when the object is empty or absent; the contract claims no
   vocabulary for it.
8. `tags` is an object of string values with keys in byte order; `lint` is a
   block holding `disable`, a list of rule ids. Both are omitted when empty,
   and neither comes from the document.

### Actions

9. An `action` block holds, in this order: `id`; `next` when the action has a
   `NextAction`; exactly one typed sub-block named by the catalog's `block`
   (the snake_case of the Type) or a `generic` block; one `condition` block
   per entry of `Conditions`, in order; one `error` block per entry of
   `Errors`, in order; and `position` last, only where the document's
   position for the action differs from what `conformance/layout` assigns.
10. The typed sub-block is written when the type is modeled in
    `conformance/flow-language/catalog.json` and the catalog's shape accepts
    the action's `Parameters`: every key is a catalog parameter, every
    required parameter is present, nested objects and lists of objects match
    their fields, and each value has its kind's JSON type. Whether the builder
    would also accept the action does not matter (the recording-analytics
    case's chat form is typed here and generic in codegen). Otherwise the
    action is a `generic` block: `type`, then `parameters = jsonencode({...})`,
    omitted when the object is empty. Typed or generic is not part of the
    round-trip invariant: a reader produces the same action from either.
11. Inside a typed sub-block the parameters are written in byte order of their
    Flow language keys, each under its catalog `attr`. Values by kind:
    - `string`, `enum`, `jsonPath`, `stringOrJsonPath`: a quoted string.
    - `ref`: the reference key, quoted (`"queue:front-desk"`); a JSONPath is
      written as itself.
    - `integer`: a number. `integerString`: a number when the value is a
      decimal string, the string itself when it is a JSONPath.
    - `map`: an object literal with keys in byte order, values by the map's
      `of` shape (strings when it has none); an object-valued `of` is a nested
      object literal with attr names.
    - `list`: a tuple, inline (`["Agent", "Customer"]`) when every element is
      a scalar, otherwise one element per line with a trailing comma, each an
      object literal with the element shape's attr names.
    - `object`: an object literal with the catalog's attr names, one line per
      field.
    - `json`: `jsonencode({...})`.
12. Inside `jsonencode` keys keep their Flow language spelling, in byte order;
    a key that is a valid HCL identifier is unquoted and any other is quoted;
    scalars and lists of scalars are inline, and an object or a list holding
    an object is multi-line. A `${cdref:...}` token inside a string stays a
    token, escaped as `$${cdref:...}`.
13. `condition` holds `operator`, `operands` (always a tuple of strings, as
    the Flow language carries them) and `next`; `error` holds `type` and
    `next`. An empty block is written `name {}` on one line.
14. A terminal action (`Transitions` is `{}`) has `id` and its sub-block and
    nothing else.
15. `position` holds integer `x` and `y`. A reader refuses a fractional
    position (`POSITION_NOT_INTEGER`).

### Strings

16. A string is double-quoted with HCL escapes: `\\`, `\"`, `\n`, `\r`, `\t`;
    any other control character (below U+0020, and U+007F) as `\uXXXX`; `${`
    as `$${` and `%{` as `%%{`; everything else raw, non-ASCII included. A
    lone surrogate is refused (`LONE_SURROGATE`).
17. Alignment follows `terraform fmt`: within a run of consecutive
    single-line attributes the `=` signs align; a blank line, a comment or a
    multi-line value ends the run. Every golden here is an fmt fixed point,
    and a gated test in `packages/tf` holds it so.

### Transitions

18. The document a reader produces is in synth normal form: `Errors` and
    `Conditions` present (possibly empty) on every non-terminal action, `{}`
    on a terminal one, keys sorted, declaration order kept. A reader takes
    positions from `position` blocks and fills the rest from the layout
    algorithm.

## Reading

19. A reader accepts exactly one resource of one of the two types per file
    (`SECOND_RESOURCE` otherwise) and refuses `count` and `for_each`
    (`COUNT_OR_FOR_EACH`), a module resource with `type` (`MODULE_WITH_TYPE`),
    a flow resource with `settings` (`FLOW_WITH_SETTINGS`), a label that is
    not `slugIdentifier(name)` (`LABEL_MISMATCH`), an attribute outside the
    settable set (`UNKNOWN_ATTRIBUTE`), a sub-block that is neither a catalog
    block nor `generic` (`UNKNOWN_BLOCK`), an action with two typed sub-blocks
    (`MULTIPLE_TYPE_BLOCKS`) or none (`NO_TYPE_BLOCK`), a duplicate `id`
    (`DUPLICATE_ACTION_ID`), an `id` the Flow language forbids
    (`INVALID_IDENTIFIER`), a `start` naming no action (`START_UNKNOWN`), a
    fractional position (`POSITION_NOT_INTEGER`), an expression where a
    literal is required (`NON_LITERAL_VALUE`), a lone surrogate
    (`LONE_SURROGATE`), and a `lint.disable` entry that is not a rule id or
    names a hard rule (`UNKNOWN_LINT_RULE`).
20. The settable attributes are `instance_id`, `name`, `type`, `description`,
    `state` (`ACTIVE` or `ARCHIVED`), `start`, `refs`, `tags`, `settings`,
    `external_invocation_enabled` (modules), the `lint` block, and the
    meta-arguments `depends_on`, `provider` and `lifecycle`. A reference
    attribute (a catalog `ref` kind, at any depth) holds a reference key of
    the right type, a JSONPath, or the full token (written `"$${cdref:...}"`,
    as any quoted string holding `${` must be); the reader normalizes the
    token to the key and records the normalization. A literal ARN there, or
    as a `refs` value, is refused (`LITERAL_ARN`). A key of the wrong type, or
    one that is not a reference key, is refused (`REF_KEY_MALFORMED`).
21. A reference attribute holding a bare expression is refused with
    `REF_EXPRESSION_REFUSED`, naming the file, line and attribute, and the
    `refs` entry to write instead. The one exception is the TypeScript
    parser's sugar (`address-sugar.json`): a resource address of a listed
    type (`aws_connect_queue.x.arn` and the others) is rewritten to the key
    (`queue:x`) plus a `refs` entry on the next regeneration, and the rewrite
    is recorded in the sidecar's `normalized` list. An address of an unlisted
    type is refused with `REF_SUGAR_UNSUPPORTED_TYPE`. The provider does not
    rewrite: it refuses the expression and says what to write.
22. A `refs` key no action references is a warning, not an error; the next
    regeneration drops it.
23. What a reader returns beside the document is the sidecar: the `refs`
    bindings by key, `lint.disable`, `tags`, the `instance_id` expression, the
    kept comments, and the normalizations it applied.

## Regeneration (TypeScript only)

24. Regenerating a companion writes the resource from the document and
    carries these from the previous file, never from the document: `refs`
    values by key (a key the document no longer references is dropped; a new
    key is written `null` with the TODO comment), `instance_id`, `tags`,
    `state`, `external_invocation_enabled`, `lint`, `depends_on`, `provider`,
    `lifecycle`, and comment lines marked `@keep` directly above an `action`
    block (keyed by `id`) or above the resource. Any other comment is
    dropped, as codegen drops them from a `.flow.ts`. `description` comes
    from the document.
25. Regenerating is idempotent: writing a companion, reading it, and writing
    it again produces the same bytes.

## The invariant

26. For every `roundtrip` case: reading `expected.flow.tf` produces the case's
    document (modulo `meta`) and the case's bindings; writing the document
    with the bindings and options produces `expected.flow.tf` byte for byte;
    and `expected.flow.tf` is a `terraform fmt` fixed point. `parse` cases add
    the non-fmt inputs a hand-written file may take.

## Module versions, aliases and views

27. A module a flow invokes by alias (`module:survey@prod`) binds to the
    alias resource's `arn`:

```hcl
resource "flowascode_contact_flow_module_version" "survey" {
  instance_id            = var.connect_instance_id
  contact_flow_module_id = flowascode_contact_flow_module.survey.contact_flow_module_id
  content_hash           = flowascode_contact_flow_module.survey.content_hash
  description            = "Survey as reviewed"
}

resource "flowascode_contact_flow_module_alias" "survey_prod" {
  instance_id                 = var.connect_instance_id
  contact_flow_module_id      = flowascode_contact_flow_module.survey.contact_flow_module_id
  name                        = "prod"
  contact_flow_module_version = flowascode_contact_flow_module_version.survey.version
  description                 = "The version production invokes"
}
```

    The version resource is keyed to the module's `content_hash` and replaced
    when it changes; the alias repoints in place. `version`, `alias_id` and
    `arn` are computed. A view binds to `data.flowascode_view.<label>.arn`.

## Error codes

`LITERAL_ARN`, `REF_EXPRESSION_REFUSED`, `REF_SUGAR_UNSUPPORTED_TYPE`,
`REF_KEY_MALFORMED`, `UNKNOWN_BLOCK`, `UNKNOWN_ATTRIBUTE`,
`MULTIPLE_TYPE_BLOCKS`, `NO_TYPE_BLOCK`, `DUPLICATE_ACTION_ID`,
`INVALID_IDENTIFIER`, `POSITION_NOT_INTEGER`, `START_UNKNOWN`,
`NON_LITERAL_VALUE`, `LONE_SURROGATE`, `LABEL_MISMATCH`, `SECOND_RESOURCE`,
`COUNT_OR_FOR_EACH`, `MODULE_WITH_TYPE`, `FLOW_WITH_SETTINGS`,
`UNKNOWN_LINT_RULE`. The provider puts the code in every diagnostic summary;
the TypeScript parser puts it on the error it throws. A `refuse` case names
the code and may name the path and a fragment of the message.
