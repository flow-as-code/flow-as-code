Running the refuse cases through a real CLI settled where the provider parts from the TypeScript reader (`4fc07f9`, `ffe0aac`, `0537341`), each observed rather than argued.
- Found along the way: Terraform validates a resource twice per plan (the second time with references to existing resources resolved), so a literal ARN in `refs` is TypeScript-only; a `null` map element reaches the provider; the framework has no dynamic attribute inside a block list, so `integer` parameters are numbers (`08e5f41`); terraform-json cannot decode a plan whose configuration has a nested attribute named `references`, so the provider's parity check reads plan JSON itself.
- Drift shows as the changed blocks, read back through the `refs` bindings; import recovers blocks and bindings through the instance inventory; `MoveState` takes `aws_connect_contact_flow` and `_module` from hashicorp/aws. `content_hash` is the hash of the content in canonical form without Metadata.
- B04j: registry docs generated by tfplugindocs from the schema, templates and examples; every example plans in the tests. B04k: goreleaser config, the protocol 6 manifest, and `release.yml`.
- B04i (2026-09-29): seven live tests (flow lifecycle with import, drift, a hard lint rule refusing the plan, module version and alias repoint, references bound to a queue and hours a pinned hashicorp/aws creates, a `moved` from a real `aws_connect_contact_flow`, and a sweeper).
