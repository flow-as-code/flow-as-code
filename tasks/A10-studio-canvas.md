# A10 Studio: canvas and editing

Deliverables: React Flow canvas per docs/02-studio-design.md; palette of modeled blocks; GenericBlock rendering with raw JSON inspector; typed ref pickers rejecting literal ARNs; refs sidebar with usage counts; worker-based inline lint; save writes FlowDoc with layout.
Acceptance: open, edit, and save the demo FlowDoc entirely offline; a lint failure blocks save for the two hard rules; layout survives reload; read the product repo's frontend-design guidance before styling.

## Shipped (2026-08-31)

- Canvas (@xyflow/react 12): one node per Action showing Identifier, Type, and a category badge; one edge per transition. Error edges are dashed red and labeled with their ErrorType; condition edges are labeled with the operand summary. Positions come from `doc.layout` with flow-core `autoLayout` filling any missing ones; dragging a node updates layout only, and a drag reported for an id that is not an Action is ignored so stale layout cannot accumulate.
- Node handles come from the action TYPE **or** from the edges that actually leave the node, whichever says a handle is needed. Every non-terminal node exposes a primary handle and an error handle so a freshly inserted block can be wired, and a node of any type that has an outgoing transition exposes the handle that transition attaches to. Deciding by type alone was a regression: React Flow drops an edge whose `sourceHandle` is absent from its node, so a transition sitting on a terminal-typed action vanished from the canvas entirely and could not be seen, rewired, or deleted. `tests/canvasUi.test.tsx` asserts the rendered edge count equals the document's transition count on a document where the two rules disagree.
- Editing v1: inspector panel generated per modeled block type (text, number, select, JSON, typed ref pickers, and Compare branch authoring); transitions rewire by dragging edge endpoints; a drag from the primary handle creates the success transition, or a condition branch on a Compare; a drag from the error handle wires the next unwired error branch. Palette grouped Interact/Set/Branch/Integrate/Terminate offers only modeled blocks and disables itself at the 250-action Connect limit. Delete removes the branches pointing at the block from the blocks that hold them, and is refused outright when that would demote a neighbour; see "Deliberate choice on delete" below. GenericBlocks render visually distinct with a raw affordance opening a read-only JSON inspector; their transitions stay rewireable and their parameters are preserved verbatim.
- Legality lives in the mutations, not the components, and it has exactly one implementation. See "The demotion invariant" below. `src/model/capabilities.ts` is now only about authoring intent (does this type have a success path, and does a drag from its primary handle mean a branch or a next action), and numeric parameters still honour the min, max, and integrality their field declares (`LAMBDA_TIMEOUT_MIN`/`MAX` for the Lambda timeout) in `setNumberParam`, because bounds are not visible to a demotion probe.
- Ref pickers: a combo of tokens already in `doc.refs` of the right type, "new reference" prompting for a validated slug, and manual entry accepting a token or single JSONPath. Literal ARNs are rejected inline with the same pattern as the no-literal-arn lint rule. The refs index regenerates via `collectRefs` on every mutation.
- Refs sidebar: every token in the doc with its type, name, alias, and usage count, counted from content rather than from the derived index. Selecting a token lists the actions holding it; each row focuses its node on the canvas. Counting is unit-tested in `tests/refUsage.test.ts`.
- Worker lint: `@criticaldynamics/flow-core/lint` runs in a module Worker, debounced on every doc change; findings badge nodes and list in a bottom panel whose rows focus the offending node. The message handler is a pure function (`src/worker/lintProtocol.ts`) tested without spawning a Worker; it validates its input and returns a structured error result rather than throwing, so one malformed message cannot wedge the worker. Environments without workers fall back to the main thread.
- Save gating: `assertSaveable` in `src/model/validate.ts` is the single write gate. It checks the hard lint rules through flow-core's `hasBlockingFindings` and structural validity against `conformance/schema/flowdoc-0.1.schema.json` (ajv, schema imported at build time so it works offline), and it runs inside `MemoryStore.write`, `DirectoryStore.write`, and the Export-as-download path. The Save and Export buttons reflect that rule but do not enforce it. They read BOTH halves of it: `blocked` from the lint worker and `schemaErrorsFor` for the schema, because deriving the button state from the lint half alone left Save enabled for a schema-invalid document and turned the click into a thrown error. Both also stay disabled until lint has seen the current doc rather than reporting the previous doc's verdict during the debounce. `parseFlowDoc` applies the same schema on the way in, for opened files and for the directory store.
- State: the FlowDoc is the single source of truth in a React context reducer; all mutations are pure functions in `src/model/` (graph mapping, mutations, capabilities, ref validation, ref usage, inspector schema), unit-tested without a DOM against the conformance schema and byte-stability through `serialize`. An ErrorBoundary keeps a render crash on screen instead of blanking the app.
- Offline: the demo FlowDoc is imported from `conformance/demo/` at build time; a test greps the built bundle for external URLs against an exact allow-list (XML namespaces, JSON Schema identifiers, and library error-message strings; nothing is fetched).

## The demotion invariant (2026-08-31, second pass)

codegen falls back to `new GenericBlock({...})` for any Action a block class cannot reproduce exactly. That is correct for genuinely unmodeled Connect actions and it is silent data loss when a canvas gesture causes it: the block loses typed authoring, and lint, the schema, and `assertSaveable` all accept the result.

The first pass guarded this per mutation, and every path it did not name stayed a hole. Three reviewers reproduced six more. The rule now has one implementation:

- `src/model/demotion.ts` answers "which Actions would codegen emit as GenericBlock?" by running flow-core's real `codegen` and reading which ids came out as `new GenericBlock`. It does not restate the inverter rules, because a second copy of them is what produced the holes. The scan walks the generated source skipping string literals and comments, so a parameter that quotes generated code cannot forge an entry, and it cross-checks itself against the generated import list. A shape it cannot account for is never reported as "nothing is demoted", because a quiet oracle makes the guard vacuous: `probeDemotion` catches the failure and returns `generated: false` carrying the reason, and `demotionDelta` turns that into an explicit `unverifiable` field. `guard()` treats `unverifiable` as a refusal, so a document the oracle cannot read cannot be edited rather than being edited unchecked. (Corrected 2026-08-31: this line previously said the oracle "throws rather than answering nothing is demoted", which described the first pass, not the fail-closed field that shipped.)
- `src/model/mutations.ts` wraps EVERY exported mutation in `guard()`, which probes before and after and throws `MutationRefused` (carrying the block ids and a sentence saying what to do instead) when a block that existed before the edit would come out generic after it. `resultDoc` enumerates the return shapes it understands and throws on anything else, so a mutation added later cannot slip past by returning its document under an unfamiliar key. `tests/mutationGuard.test.ts` enumerates the module's exports and fails if any mutation is unwrapped.
- A block the gesture just created is exempt. A newly inserted MessageParticipant has no transitions and is legitimately inexpressible until it is wired; nothing was lost, and lint's terminal-blocks and error-branches findings are what guide the user to finish it. The guard protects ids that existed before the edit.
- The studio and codegen no longer disagree about what is generic. The canvas node and the inspector both read the oracle, so a modeled block codegen cannot currently express says so ("generates as GenericBlock") instead of presenting itself as fully typed.
- Refusals are shown, never swallowed. `commit()` in `src/state/studio.tsx` turns both a `MutationRefused` and a plain `undefined` result into a transient `NoticeBar` message; `Canvas.tsx` used to discard both with `if (next !== undefined)`.

Deliberate choice on delete: deleting a block detaches the transitions pointing at it, and on the demo flow deleting `hang-up` would leave four MessageParticipants inexpressible. The mutation refuses and names them. It does not repair them, because repairing means inventing a destination for someone else's transition, which is a larger edit than the user asked for and one they cannot see the whole of. The route forward is in the message: rewire those edges to another block first, then delete. `tests/mutations.test.ts` walks that route end to end on the demo flow.

Corrected in A11: the confirmation prompt said "N transition(s) still point at X and will be detached. Delete?" and then the mutation refused, so on the demo flow confirming the deletion of `hang-up` deleted nothing. `Inspector.onDelete` now runs the mutation before prompting: a refusal is shown as a notice with no prompt, and the prompt appears only for a delete that will happen. Covered by `tests/inspectorUi.test.tsx`.

Proof it is not vacuous: neutering `guard()` so the delta is always empty fails 13 tests across 5 files (`mutations`, `modelCorrectness`, `mutationGuard`, `studioState`, `canvasUi`). Restoring it returns the suite to green.

## Also fixed in the second pass

- Both ends of `rewireEdge` go through the same code and the same guard. The target end previously applied the new destination with no checks at all, so moving a `CheckHoursOfOperation` branch or next edge demoted it on the demo flow. The only check left in the source-end path is anti-clobber (dropping a next edge on a block that already has one would overwrite a transition, and lost content is invisible to a demotion probe because the result stays expressible).
- `setMessageBody` enforces "exactly one body" at runtime, not only in the types. Passing `undefined` used to delete every body parameter and write a block the schema rejects.
- `RefPicker` renders "(choose a reference)" as a disabled option on a required field, and refuses the selection if something picks it anyway, instead of deleting a reference the block cannot do without.
- `refUsage` counts over the whole action, not just its Parameters. A token used only in a condition operand showed a count of 0 and read as dead.
- The inspector clears `numberErrors` and `pendingBody` when the selection changes, compares a number field against `""` rather than the string `"undefined"` for an absent parameter, and drops blank operands instead of authoring `[""]` from an emptied field. The branch editor now appears whenever a block HAS branches, not only when it may gain one, so a `CheckHoursOfOperation`'s two fixed branches are editable.
- `useLintWorker` has a watchdog. A worker that boots, accepts the message, and never answers used to leave `lintPending` true and Save disabled behind "Checking..." for the rest of the session; after `LINT_TIMEOUT_MS` it is terminated and the lint runs on the main thread.
- The reducer ignores a `mutated` action carrying the document it already has. `moveNode` returns the same reference for an unknown id, and setting `lintPending` for it meant nothing would ever lint that document again.
- Bundle: the entry chunk had grown past Vite's 500 kB warning. The warning limit was not raised. Compiling the schema with ajv's standalone generator (the preferred fix) is blocked on ajv 8, whose generated module emits `require("ajv/dist/runtime/ucs2length")` for the minLength/maxLength helper even with `code.esm` set, which does not load in a browser; the ways around that are hand-editing generated validator code or setting `unicode: false` and quietly changing what minLength means for non-BMP characters, and neither belongs inside the save gate. The chunk is split by dependency instead (react, reactflow, ajv), which also makes the app chunk cacheable across studio releases.

## Notes and known trade-offs

- Dragging from the primary handle of a Compare appends a branch whose operator is `Equals` with a single empty operand. The branch has no meaning until the inspector fills it in; an invented operand would read as authored. Lint has no rule for an empty operand yet. (A11: the inspector used to refuse the same value it could reach by dragging, telling the user "a branch needs at least one operand". Both surfaces call `normalizeOperands` now, so an emptied field means the placeholder and blanks between commas are still dropped.)
- Switching a message body between Text and SSML carries the previous string over rather than discarding it. That can leave SSML that is not wrapped in `<speak>`, which nothing in the toolchain flags today.
- Bundling ajv and the schema costs about 130 kB minified, now in its own chunk. That is the price of validating at the write path in the browser; the alternative was a gate only the UI enforced.
- The demotion oracle runs `codegen` on the document before and after every mutation. Results are cached per document value in a `WeakMap`, so a chain of edits pays one codegen per new document, and codegen is pure string building over at most 250 actions. If that ever shows up in a profile, the fix is a seam in flow-core exposing the inversion result directly, not a copy of the inverter rules in the studio.
- `docToGraph` skips a transition whose target Identifier is not in the document. Such a transition is still preserved in the file and re-emitted, but it cannot be drawn as an edge, because there is no node for it to end at. No mutation can produce one (`deleteBlock` detaches them), so this only bites a document authored elsewhere. A11 stopped it from being invisible: `danglingTransitions` reports them, the source node carries a count, and `DanglingPanel` lists each one. Rewiring one from the canvas still needs a block with that Identifier to exist.
- A block whose neighbours would be demoted cannot be deleted until those edges are rewired. That is a real cost on a densely wired flow and it is the deliberate trade described above.
- Two studio tests read `dist/`: `tests/bundle-offline.test.ts` (no external URLs) and `tests/bundle-boot.test.tsx` (the built bundle mounts, which is where a CommonJS dependency consumed as a named import would fail in a way the source tests cannot see). Without a build, exactly one case fails, naming `npm run build`, and the rest skip. `README.md` and `vitest.config.ts` say both files, not just the first. Everything else runs on a clean `npm ci && npm test` because vitest resolves flow-core to its sources.

## DocStore seam (for A11)

Persistence goes through `src/store/types.ts`:

```ts
interface DocStore {
  list(): Promise<DocRef[]>;
  read(name: string): Promise<{ doc: FlowDoc; text: string }>;
  write(name: string, doc: FlowDoc): Promise<void>;
}
```

A10 ships two implementations: `MemoryStore` (backs the built-in demo via `createDemoStore()` and single files opened through `<input type="file">`, with Export-as-download for getting edits back out) and `DirectoryStore` over the File System Access API (feature-detected; edits real `*.flowdoc.json` files fully offline in Chromium). Any new implementation must call `assertSaveable` in `write`; the gate belongs to the write path, not to the caller. A11 added `BridgeStore` over the `flow-cli studio` server behind this same interface (JSON over HTTP, with a long-polled event stream rather than a websocket); nothing else in the app touches persistence.
