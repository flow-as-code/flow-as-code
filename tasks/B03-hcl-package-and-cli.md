# B03 `@flow-as-code/hcl` and the CLI companions

Deliverables: `packages/hcl`, a browser-safe package that reads and writes HCL as a third view over FlowDoc, implementing `conformance/hcl/README.md`; the CLI commands that create, convert, emit and watch `.flow.tf` companions; bridge protocol 2 for the studio.
Acceptance: `print(parse(text))` is byte-exact and `format(parse(text))` equals `tofu fmt`'s output for every committed Terraform file; `toFlowDoc(fromFlowDoc(doc))` reproduces every `conformance/hcl/roundtrip` document and `fromFlowDoc` reproduces its golden; the parse, refuse and regenerate cases pass; `flow-cli init --author tf`, `codegen --to tf`, `synth` of a `.flow.tf`, `convert`, `export --author tf` and `emit --target flowascode` work; the watcher pairs `.flow.tf` companions and re-syncs within a second.

## Notes (2026-09-28, B03a)

- The lexer keeps every character: horizontal whitespace rides on the next token, comments are tokens (a line comment's carries its newline, as hclsyntax's does), and quoted strings and heredocs are split into literal runs and `${ }` / `%{ }` sequences with escapes kept verbatim. The parser covers the native syntax: bodies, labelled and single-line blocks, and every expression form (templates, tuples, objects with newline or comma separators, traversals with attribute, index and splat steps, namespaced calls, unary, binary and conditional operators, parentheses, and `for` expressions). Every node records its first and last token.
- `format` ports hclwrite's formatter pass for pass (line splitting, indent by bracket depth, `spaceAfterToken`, and the `=` and trailing-comment alignment cells, including hclwrite's rule that a line opening a multi-line value is left out of the alignment run). Probed first against `tofu fmt` for the rules the committed files do not exercise (`!`, `{ }`, blank lines, comment alignment). Across all 89 committed Terraform files it agrees with `tofu fmt` byte for byte, which found one committed file that was not formatted: `conformance/emit-tf/hostile-text/validate/stubs.tf`, now formatted (its contents are unchanged).
- The gated comparison excludes `refuse/lone-surrogate`, which HCL's own parser refuses ("Cannot encode character U+d800 in UTF-8"); the contract README now says the provider passes that case on Terraform's parse error while this package raises `LONE_SURROGATE`.
- Wiring: the workspace and root `tsconfig.json`, `sync:license`, `PACKAGE_NAMES.hcl` in core and the studio's demo copy, the packaging test's tables, the site's package page and llms.txt roles, CI's gated lane and publish dry-run loop, and every sentence that counted five packages (the README, CONTRIBUTING, the changeset README, the landing page, core's README, and the release workflow's comments, which now say the new package's Trusted Publisher follows its first hand publish).
- Neutered and watched go red: the multi-line alignment exclusion (65 files), the no-space-around-dot rule (74 files), and `//` comments in the lexer.

## Notes (2026-09-28, B03b, reader and writer)

- `fromFlowDoc` lays the resource out line by line with its indentation and hands the text to `format`, so `=` alignment is hclwrite's, not a second implementation of it. It reproduces all twelve `hcl/roundtrip` goldens and all seven `hcl/regenerate` goldens byte for byte, and writing its own output as `previous` reproduces it (rule 25).
- `toFlowDoc` reads every `hcl/roundtrip` golden to its document and bindings, every `hcl/parse` input to its document and sidecar, and refuses every `hcl/refuse` input with its code and path. A sweep holds the round trip over every FlowDoc 0.2 committed under `conformance/` and `examples/` (80 documents), each written, read back and compared with its view.
- The sweep found what the contract had not said, now rules 15, 18 and 26: an exported flow's console positions are fractional, and the writer rounds them; `content.Metadata`, which export keeps, is not part of any view (codegen drops it too); and nothing wired reads as `{}` only on a type the catalog marks terminal or does not model, since the builder writes empty `Errors` and `Conditions` on any other (a waiting `MessageParticipantIteratively` in the participant case).
- Contract fix: `refuse/refuse-module-sugar` refused `flowascode_contact_flow_module.question.arn`, an address the sugar table lists, so the case contradicted rule 21. It is now `refuse/refuse-alias-sugar`, refusing the alias resource's address (`flowascode_contact_flow_module_alias.question_prod.arn`) and naming the `refs` key that binds it. Rule 21 and `address-sugar.json` now say which shape `REF_SUGAR_UNSUPPORTED_TYPE` covers (`<type>.<label>.arn` and `data.<type>.<label>.arn` of an unlisted type); every other expression is `REF_EXPRESSION_REFUSED`.
- Neutered and watched red, then restored: the `@keep` filter, the terminal normal-form rule, the stale-key drop, the sugar binding, position rounding, the literal-ARN check on `refs` values, and carrying `instance_id`.

## Notes (2026-09-28, B03b, emitter)

- `emitFlowascode` mirrors `emitTf`'s inputs and refusals (address map keyed three ways through core's `lookupRefValue`, expressions checked for literal ARNs, newlines and comment markers, slug names, one address per document, every problem listed) and writes rule 28's three files. Each resource is `resourceLines`, the same writer `fromFlowDoc` uses, so a resource in `flows.tf` and a companion differ only in the banner and the bindings.
- It resolves an unaliased in-set module to the module resource's `arn` as well as an aliased one to the alias resource's; `emitTf` resolves only the aliased form in set. The flowascode refs map needs no shared locals, so the dependency cycle `emitTf`'s per-document locals avoid does not arise.
- `conformance/hcl/emit/` has one case per `emit-tf` case (a test holds the two lists equal), each with `validate/stubs.tf` copied from its `emit-tf` twin and `validate: "skip"` until B03e. The test reads every flow and module resource in each `flows.tf` back to its document.
- Neutered and watched red, then restored: in-set module resolution, the literal-ARN check, the duplicate-address check, and the alias resources.
- `docs/03-tf-emitter.md`, `packages/tf/README.md` and the `emit.ts` header no longer call the reverse direction deferred; they point at this package for the shape that is read back. docs/06 describes `--target flowascode`.

## Notes (2026-09-28, B03c, commands)

- `packages/cli/src/companion.ts` is the one place a companion of either kind is generated or read: `generateCompanion` (core's `codegen` or hcl's `fromFlowDoc`), `readTfCompanion` (hcl's `toFlowDoc`, its `HclError` turned into a `CliError` that keeps the file, line, column and code), and `keptFromTs`. The CLI now depends on `@flow-as-code/hcl`.
- `codegen --to ts|tf` defaults to the document's `meta.sourceKind`; `synth <name>.flow.tf` parses in process and stamps `sourceKind: "tf"`; `export --author tf`; `emit --target flowascode` writes exactly `emitFlowascode`'s bytes; `convert --to ts|tf [--address-map] [--keep-old]` refuses to replace an existing companion, carries `@keep` lines across (`//` and `#` rewritten), restamps `meta.sourceHash` and `meta.sourceKind`, deletes the old companion unless `--keep-old`, and prints what does not carry as `note:` lines.
- To carry comments from a `.flow.tf` into TypeScript, core's `codegen` takes `options.keep` in place of the comments `previous` holds, and exports `extractKeepComments` for the other direction; hcl's `fromFlowDoc` takes `keep` likewise.
- Neutered and watched red, then restored: core's `options.keep`, and the `//` to `#` rewrite.

## Notes (2026-09-28, B03c, watcher, pairing and protocol 2)

- The watcher routes `.flow.tf` as it routes `.flow.ts`: a change is read in process through `readTfCompanion` (no child process), stamped `sourceKind: "tf"`, and synced under the same `meta.sourceHash` dirty guard. A `.flow.tf` edit reaches the document within the one-second budget, measured by the same test shape as the `.flow.ts` one. A refused file is an `error` carrying the contract's code; what the reader noticed without refusing (an unused `refs` key, sugar read as a key) rides on `synced` as `warnings`. A name with both companions is an `error` on every change, and nothing syncs until one goes.
- `bridge/pair.ts` resolves the companion to write as: the caller's `sourceKind`, then the companion on disk, then `meta.sourceKind`, then `ts`. The plan put `meta.sourceKind` before disk; disk comes first so a save can never write a second companion beside the one there, and a write whose requested kind disagrees with the disk is refused with a pointer to `flow-cli convert`. `ensureCompanions` replaces `ensureBuilderFiles`, writing the kind `meta.sourceKind` names. `createPair` backs `POST /bridge/docs` and refuses (409) when the document or either companion exists.
- Protocol 2 is in both byte copies (the byte-equality test holds them). The studio needed only its conflict dialog's labels and test fixtures to follow; the companion badge, New flow dialog, surfacing sync warnings and `lintDisable`, and the flowascode export are B05.
- `init --author tf` writes the document and its `.flow.tf` and no `package.json` (HCL is not run), refusing when either companion is already there.
- Neutered and watched red, then restored: the watcher's and the bridge's ambiguity checks, `createPair`'s refusal (the first version of that test passed with the check removed, because the kind mismatch refused first; it now posts the same kind again and asserts the file is untouched), `lintDisable` on a write, `sourceKind` on a conflict, and the watcher's `warnings`.

## Notes (2026-09-28, review of B03b to B05b)

A review workflow (five dimensions, each finding reproduced by an adversarial verifier) confirmed 25 defects; all are fixed, each with a test shown to fail with its fix removed.

- Reader: `refs` placed after the actions no longer lets a `null` entry erase the address an action writes (carry merges the two sources after reading); one key binds one address, so an address whose key `refs` binds elsewhere, or two addresses reading to one key (`aws_lambda_function.x.arn` and `data.aws_lambda_function.x.arn`), are refused with `REF_EXPRESSION_REFUSED`; a `null` refs entry takes the action's address in the sidecar too; a parameter set to `null` is unset, as Terraform reads it; a parenthesized value reads as its inside, and an object, list or map parameter holding a literal of another shape is refused; an attribute, object key, or `lint` or `lifecycle` block given twice is refused with the new code `DUPLICATE_ATTRIBUTE` (HCL refuses these as "Attribute redefined", so the provider passes that case on Terraform's error); the banner's own line mentioning @keep is not a kept comment.
- Writer and emitter: a `json` kind holding something other than an object, and a `ref` field holding anything but a token of its type or a JSONPath, are written generic (the latter through one predicate, `isRefFieldValue`, shared with the contract); `for`, `if`, `in`, `null`, `true` and `false` are quoted as object keys; an integerString is a bare number only when a JavaScript number holds it exactly; keys sort by code point (UTF-8 byte order, as the contract says) rather than by UTF-16 code unit; two module aliases that would label one alias resource are refused.
- CLI: `convert` refuses to delete an old companion holding edits the document lacks (`--force` overrides); `codegen` restamps the document it pairs with and refuses to add a second companion; `export --author` records a document whose other companion is in the way, or whose existing companion does not parse, as a failure and writes the rest; `synth` of a `.flow.tf` stamps the hash of the file's bytes (a byte order mark decodes away) and refuses a file that is not UTF-8.
- Bridge and watcher: resolving a disk conflict toward the document works (it was a 500: the write was not forced); the code side of a conflict over a `.flow.tf` naming another flow is an error, not a document to adopt; a document already restamped for the companion's current content is in sync; removing one of two companions syncs from the survivor; the README counts eight routes.
- Studio: a conflict the studio raises itself carries `sourceKind`, so the dialog names the `.flow.tf`.
- New conformance cases: `refuse/duplicate-attribute`, `refuse/refuse-sugar-conflicts-refs`, `refuse/refuse-sugar-two-addresses`, `parse/sugar-null-binding`, `parse/null-parameter`, `parse/parenthesized-values`, `regenerate/refs-after-actions`, `regenerate/keep-under-banner`.
