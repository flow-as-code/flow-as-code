# A09 flow-tf emitter

Deliverables: per docs/03-tf-emitter.md with golden-file tests; `emit --target tf` wired in the CLI; awscc module version/alias scaffold.
Acceptance: with a complete address map, `terraform validate` passes on emitted output (CI uses an OpenTofu binary); with an incomplete map, validate fails on the TODO placeholders; goldens byte-stable.

## Notes (2026-08-31, implementation)

- Landed as `packages/tf/src/{emit,template,hcl,write}.ts`. `emitTf(docs, options)` is pure (path to content, sorted, byte-stable); `writeTf` is the filesystem wrapper. Goldens: `conformance/emit-tf/{demo-complete-map,demo-incomplete-map,module-set,hostile-text}`, regenerated with `UPDATE_GOLDENS=1`.
- The CLI wiring (`emit --target tf`) is NOT part of this change; it belongs to A08 and flow-cli was left untouched.
- Templates are escaped whole and reference interpolations substituted afterwards through collision-proof sentinels, so caller text containing `${`, `%{`, or a sentinel lookalike survives byte for byte. `src/__fixtures__/hcl-template.ts` is a reference implementation of the template grammar written from the HCL spec; the gated tests assert a real `tofu` binary agrees with it on every emitted template.
- `tofu validate` found a design flaw in the docs/03 shape: with one shared `local.flow_refs`, a module whose alias address sits in the map makes the map depend on resources rendered from it, and both tools reject the cycle. Addresses of resources the set emits itself now live in a per-document `merge(local.flow_refs, { ... })` local. Mutually referencing flows are still a cycle, because they are one.
- Verified against hashicorp/aws 6.62.0 and hashicorp/awscc 1.99.0 with OpenTofu 1.12.6: argument names, the `type` argument on flows only, `awscc_connect_contact_flow_module_version.version`, and `awscc_connect_contact_flow_module_alias.contact_flow_module_alias_arn`. Those were the versions on the day; CI has since bumped the fixtures twice and exercises 6.64.0 and 1.101.0 (`conformance/emit-tf/*/validate/providers.tf`, which is the live answer). Since 2026-09-10 the drift canary also runs the same cases against whatever the emitter's own `>= 5.0` / `>= 1.74` resolves to, so "the newest provider still accepts this" stops being a claim from one afternoon.
- Emitted output is `tofu fmt` clean, asserted in the gated suite.
- `tofu init` needs the network and minutes on a cold provider cache, so every test that runs a binary is gated behind `RUN_TOFU_VALIDATE=1`, which CI's emit-tf job sets. An ungated test reads `.github/workflows/ci.yml` and fails if that job stops setting it, so the gate cannot go quiet.
- Deviation from docs/03 line 8: `templatefile("${path.module}/flows/<name>.flow.tftpl", ...)`, not a bare relative path, so the output works when consumed as a terraform module.

## Notes (2026-09-04, first real CI run)

The gated suite had never run on a hosted runner. The first one hung: all four "renders every template" cases spent their full 120s timeout in `spawnSync tofu ['console','-no-color']` and the job took 610s.

- Cause, and it is not a version. `opentofu/setup-opentofu@v1` installs a wrapper by default (input `tofu_wrapper`, default true): a node script named `tofu` that runs the real binary through `@actions/exec` without passing `options.input`. `@actions/exec` leaves `stdio` at node's default, so the child's stdin is a pipe the wrapper never writes to and never ends. `tofu console` in piped mode evaluates at EOF, so it waited forever. Reproduced locally by spawning `tofu console -no-color` with that same stdio: hangs on OpenTofu 1.7.0 and on 1.12.6 alike, where the identical expression through a pipe that does close answers in about 30ms on both.
- Fix, in the harness rather than the environment: `tofuEvaluateString` writes the expression into an `output` block, runs `apply -auto-approve -input=false` (no providers, so offline and credential-free) and reads it back with `output -raw`. Nothing reads stdin. It still crosses the CLI boundary base64-encoded, which is what keeps it byte-exact through `hostile-text`, and it now rejects a non-base64 answer instead of decoding it to silent garbage.
- Second defect found while checking the fix on both versions: the provider cache was never being used. OpenTofu installs from upstream until a lock file already records upstream checksums, and every test materializes a fresh configuration directory, so every `init` re-downloaded aws and awscc. On 1.7.0 the parallel re-extraction into the one cache directory also broke running provider binaries ("Unrecognized remote plugin message") and produced lock file checksum mismatches. The harness now sets `TF_PLUGIN_CACHE_MAY_BREAK_DEPENDENCY_LOCK_FILE=1`, which is exactly the documented switch for cache-installed providers; the lock files it weakens are in throwaway directories that are never committed or reused. The gated tf plus studio suite went from 305s to 13s warm.
- CI drops the wrapper (`tofu_wrapper: false`). None of its `stdout`/`stderr`/`exitcode` outputs are used, and it reports 1 for every non-zero exit, which loses the real status the incomplete-map test asserts on.
- The job now runs a matrix, `["1.7.0", "1.12.6"]`: the floor the emitter promises and a current release. `CORE_VERSION_FLOOR` in `src/emit.ts` is the single source for that floor, it lands in every `versions.tf.example`, and an ungated test asserts the CI matrix still contains it and still has more than one entry. The two matrix entries run in parallel, so wall time is unchanged; the provider cache is keyed per version so they do not race to save one key.
