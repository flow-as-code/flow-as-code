Model the Customer Profiles actions (tasks/D03). `AssociateContactToCustomerProfile` (Associate contact to profile: `profileId` and `contactId`, each static or a JSONPath, with `next` and the catch-all) writes its two ids in `ProfileRequestData` and an empty `ProfileResponseData` list, the shape the console writes. `CreateCustomerProfile` (Create profile: a `request` object whose keys are the page's 55 fields or `Attributes.<name>`, each value static or a JSONPath, and a `response` list of the same names, stored under `$.Customer`, with `next` and the catch-all) writes both containers, empty when nothing is chosen; a name outside the page's lists keeps the block generic. `UpdateCustomerProfile` (Update profile) takes the same fields and updates the profile a preceding Get or Create profile found. `GetCustomerProfile` (Get profile: an `identifier` `{ name, value }` or a `search` of one to five criteria with an `AND` or `OR` operator, exactly one, the same `response` names, and `onError`, `onMultipleFound` and `onNoneFound`) writes `IdentifierValue` as every published flow spells it; a block searching by a named field, as AWS's step-by-step guide flows do, stays generic. `GetCustomerProfileObject` (Get profile object: `profileId`, `objectType`, and `latest: true` or an `identifier`, exactly one, with the page's Asset, Order and Case `response` names, and `onError` and `onNoneFound`) writes `UseLatest` as the string `"true"`. Each is unrestricted by flow type and channel. The catalog's `keys` and `keyPatterns` may now sit on a list of strings as well as a map. The HCL writer and reader take them as the typed `associate_contact_to_customer_profile`, `create_customer_profile`, `update_customer_profile`, `get_customer_profile` and `get_customer_profile_object` sub-blocks, which no published flowascode provider accepts until the release that carries them. The `unknown-actions` passthrough fixture holds `UpdateCase` in place of `UpdateCustomerProfile`, carrying its queue token. The studio's inspector chooses request fields from the page's list, types custom attributes, and ticks response fields; Get profile and Get profile object blocks switch between their two forms, clearing the other. The service has not yet been asked about these types (rule 43 in `conformance/flow-language/actions.md` is probe pending), so their required keys, branches and spellings are the AWS pages' and published flows' reading.
