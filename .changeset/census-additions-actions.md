Model the census additions (tasks/D09), the Types no Developer Guide category page lists. `TransferParticipantToThirdParty`, the Transfer to phone number block, is a builder block from the kept export (`conformance/flow-language/exports/`): its number a JSONPath, its time limit a positive integer, and `continueFlow` true with the Call failed, Timeout and catch-all branches, which the service requires in that form, or false with the catch-all and either of the others; the catalog's shape makes `conditional-shape` hold the first form, and its `channels` is `VOICE`. `LoadContactContent`, the admin guide's Get stored content block, is a builder block (`next` and the catch-all; the class writes the page's one `ContentType`, `EmailMessage`), a codegen inverter, a catalog entry and an insertable studio block; its catalog `channels` is `EMAIL`, so `channel-restricted-action` warns wherever it appears. The HCL writer and reader take them as the typed `transfer_participant_to_third_party` and `load_contact_content` sub-blocks, which no published flowascode provider accepts until the release that carries them. The `unknown-actions` passthrough fixture no longer holds either, and the Terraform cookbook's generic recipe uses `StartVoiceIdStream`. The service has not yet been asked about these types (rule 47 in `conformance/flow-language/actions.md` is probe pending), so their required branches and flow types are the AWS pages' reading.
