`flow-cli lint` and `flow-cli emit` take several directories or files. Each argument is its own set, linted or emitted whole and never merged with the next, so cross-document rules and module aliasing stop at a set's edge; findings and emitted files name their set, the exit status is the worst across sets, and `emit` refuses an `--out` that would merge sets. `flow-cli lint --format json` is now `flow-lint-report/0.1`, documented field by field in the CLI README with a JSON Schema at `conformance/schema/lint-report-0.1.schema.json`; `summary` and `findings` are where they were, and each finding gained `set`.

`flow-cli emit --target flowascode --instance-id-expression <expr>` passes the emitter's `instanceIdExpression` through: every resource's `instance_id` takes the expression and no `variables.tf` is written, for a root that declares the instance itself.

`flow-cli codegen --banner <text>` and `codegen()`'s `banner` option write one extra comment line after the two fixed ones, kept across regenerations that omit it and removed by an empty one, so a generator that owns a document can say so in its companion. Codegen output is left unchanged by Prettier 3 at the repository's settings in two more shapes (a string under a wide key past the print width, inline arguments after a broken config), and every export golden is now held to that fixed point.

New lint rule `attribute-set-before-read` (warning, set-wide): a `$.Attributes.<name>` read in message text that no document in the linted set writes through UpdateContactAttributes speaks an empty value. A single document reports nothing, since attributes cross flows.

The studio marks a FlowDoc whose `meta.generator` is not this toolchain's own (`core@...`, `cli@...`) with a "Generated by" badge, and asks once before the first edit, saying the next run will overwrite it; nothing is written to the document for it.
