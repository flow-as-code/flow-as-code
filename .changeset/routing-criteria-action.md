Model `UpdateRoutingCriteria` (Set routing criteria, tasks/D07). The class takes `steps`, a list of steps or a JSONPath to one, with `next` and the catch-all. Each step holds an `expression` and an optional `expiresAfterSeconds`, written as `Expiry.DurationInSeconds` in a decimal string; only the last step may leave it out. Expressions are built by three new helpers: `attributeCondition(name, value, level)` (a predefined attribute's name and value, 1 to 64 characters each, the value also a JSONPath, and a level from 1 to 5, written as a JSON integer with `NumberGreaterOrEqualTo`), `and(...)` (one to eight requirements) and `or(...)` (one to three requirements or ANDs, at the top only). `RoutingExpression` types them, and codegen writes a stored expression back as those calls. The type is legal in inbound, customer queue, transfer to agent and transfer to queue flows and modules, on every channel. In the catalog the expression is a `json` value inside typed steps, and `Steps` is the first list marked `dynamic` (docs/adr/0009). The HCL writer and reader take it as the typed `update_routing_criteria` sub-block with `expression = jsonencode(...)`, which no published flowascode provider accepts until the release that carries it; a JSONPath `Steps` stays a `generic` block. The studio's inspector edits the steps one at a time, each expression in the JSON editor and each expiry in seconds, or switches to a JSONPath. The `unknown-actions` passthrough fixture holds `CompleteOutboundCall` in its Chime voice connector form, which stays generic, in place of `UpdateRoutingCriteria`, carrying its queue token. The service has not yet been asked about this type (rule 45 in `conformance/flow-language/actions.md` is probe pending). Its Type spelling, required keys, levels and limits are the AWS pages' reading. Two public sources say the service requires the Type `UpdateContactRoutingCriteria`, and rule 45's first probes settle it.
